## 2. Candidate appliances

| | Breaches addressed | Protocol surface / verifiability | Client | PQ readiness |
|---|---|---|---|---|
| HTTPS reverse proxy (QEDOS) | Web-facing only | Large: TLS 1.3 + HTTP parsing | Browser | Key exchange only; WebPKI certs must stay ECDSA/RSA in 2026 |
| **Remote-access VPN (WireGuard + Rosenpass)** | **VPN + RDP exposure; no passwords → credential-leak entry impossible** | **Small: fixed Noise IKpsk2, no negotiation, ProVerif/Tamarin analyses exist** | wg + rosenpass | **Full: own trust anchor, PQ PSK via Rosenpass** |
| Zero-trust proxy | Large | Largest (TLS + OIDC/SAML + policy) | Browser/agent | Same as HTTPS |
| DNS resolver | Small | Medium | None | DNSSEC PQ not standardised |
| HSM | Post-compromise only | Small | PKCS#11 | PKCS#11 3.2 has ML-DSA/ML-KEM **(unverified)** |

Decision (user, 2026-10-18): **VPN gateway first, HTTPS proxy second, on a shared base.**

## 3. Platform facts

- **Microkit 2.3.1** (2025-09, seL4 16.0.0). Boards incl. `qemu_virt_aarch64`, `qemu_virt_aarch64_el1` (KVM without nested virt). Linux-aarch64 SDK published.
- **Proof coverage** ([verified configurations](https://docs.sel4.systems/projects/sel4/verified-configurations.html), [roadmap](https://sel4.systems/roadmap.html)):
  AArch64 functional correctness + integrity done; confidentiality completed 2026-08-24.
  QEMU virt is **not** a verified platform (RPi4/5, i.MX8M, ZCU102 etc. are). MCS (AArch64 Q3/27) and SMP (Q3/28) unverified.
  DMA/IOMMU, boot and debug builds are outside the proofs. Microkit and sDDF are unverified.
- **rust-sel4** (git only, `5.0.0-dev`, toolchain `nightly-2026-08-21`): `sel4-microkit`, `sel4-shared-ring-buffer`, driver adapters.
  [rust-microkit-http-server-demo](https://github.com/seL4/rust-microkit-http-server-demo) (smoltcp + rustls + virtio) is the closest template but pins Microkit 2.1.0 / x86-64 host.
- **sDDF 0.7.0 / LionsOS 0.4.0** (2026-08): C drivers; LionsOS has a firewall example worth reading.
- **Attestation**: QEMU arm virt supports `tpm-tis-device` + swtpm; U-Boot does measured boot. No seL4 TPM driver found **(unverified)**. Arm CCA in QEMU still RFC; no seL4 Realm support.

## 4. Crypto and verification tooling

- **libcrux** (Cryspen): ML-KEM, ML-DSA, X25519, ChaCha20-Poly1305 verified via hax; SHA-2/3, HKDF, AES-GCM, Ed25519 from HACL*. P-256 unverified. no_std with allocator. Pre-1.0.
  Symbolic Software (2026-02) reported 3 defects in verified code and 6 in unverified code ([post](https://www.symbolic.software/blog/2026-02-12-cryspen-response)); adversarial source, Cryspen's response not reviewed.
  → pin versions, run [Crucible](https://www.symbolic.software/blog/2026-03-23-crucible/) + Wycheproof in CI.
- **rustls 0.23** works no_std via the Unbuffered API; PQ hybrid only in the aws-lc-rs provider → a custom libcrux `CryptoProvider` is needed (HTTPS phase). `SigningKey` lets signing be delegated over IPC.
- **PQ authentication in WebPKI**: RFC 9881 (ML-DSA in X.509) published, but CA/B Forum has not allowed it and Chrome is going Merkle Tree Certificates. Public HTTPS must present ECDSA P-256/RSA in 2026.
- **Verus** + **Vest** (verified parser/serializer combinators, demonstrated on TLS 1.3 messages): first choice for wire formats and state machines.
  **Kani** now has contracts/loop invariants (unbounded proofs). **bolero** shares harnesses between fuzzers and Kani. Prusti is dead.
- **Constant time**: no maintained binary-level tool for current rustc (haybale-pitchfork status **unverified**). Use source-level secret-independence (libcrux/Vest) + `dudect` statistical testing on target, and record the residual risk.
